Firing orders are the mechanism Brick by Brick uses to guarantee knowns. Each brick is a fired order — a verified unit that can't be skipped — and the wall is built by stacking them in sequence. The rule is that no brick ships without its receipt, and no order fires without a brick behind it.

## The IFTTT model

Brick by brick modeled on If This Then That.

**If** this condition, **then** that brick gets laid. The condition is the trigger. The brick is the action. The receipt is the proof the action fired.

- **If** a lesson is learned and verified, **then** a brick is laid.
- **If** the receipt disagrees with the claim, **then** graceful validation offers the next option — never a hard no.
- **If** a new app is named, **then** it gets a numbered position in the taxonomy registry.
- **If** a rule is added, **then** the biometrics gate opens first.

Every if-then pair in the system is a brick. The condition is inspected. The action is proven. The receipt is checked by something outside the brick.

## The trust framework

Everything operates off trust. Ground zero is the trust framework.

| Trust element | System element |
|---------------|----------------|
| Grantor | Avery — creator of the idea, declares the trust |
| Beneficiary | Avery — receives what the idea becomes |
| Trustee | The Hand / the Stork — executes the trust instrument, not the beneficiary's wishes |
| Trust instrument | The Briefcase — the written declaration, the constitution |
| Assembly | The UNA — the Fact Factory (factfactory.com) |
| Carrier | The Stork — delivers ideas, never builds |

- **Revocable is the default.** Every new idea enters as a revocable trust unless explicitly declared irrevocable.
- The trustee follows the document — the declaration and bylaws — nothing else. The beneficiary cannot direct the trustee.
