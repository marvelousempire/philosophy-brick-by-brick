# 001 — Founder's Core Intent: Dynamic yet modular

> **DYNAMIC YET MODULAR**

This is the founder's governing intent across Avery Goodman, Automata, ACT V5, Grand Canvas, Nephew (Function), Niece (Form), makeWAY, microsites, and all philosophy families.

## Founder's constructive reasoning
**Dynamic**: adapt, evolve, respond and reconfigure. **Yet**: preserve independence while changing. **Modular**: each canvas, micro-slice, widget, service, and philosophy has a clear identity, purpose, interface, permissions and replaceable boundary.

**Founder's epiphany:** Change must never come at the expense of independence. Independence must never prevent change.

## Must haves
1. Adaptability and composition from reusable, well-defined pieces.
2. Stable boundaries, explicit dependencies and recoverable state.
3. Local-first privacy, controlled permissions and device-aware presentation.
4. Real tests and receipts before declaring implementation operational.
5. Function (Nephew) and form (Niece) both honor the same rule.

## Must denies
1. **MUST DENY** rigid designs that prevent adaptation.
2. **MUST DENY** monoliths that unnecessarily bind unrelated components.
3. **MUST DENY** hidden dependencies, unsafe changes or unapproved data transfers.
4. **MUST DENY** changes that destroy component identity or replaceability.
5. **MUST DENY** claims of completed wiring without working acceptance evidence.

## Application
This is a policy and design rule, not proof that runtime, UI, or deployment enforcement is finished. Each repository should apply it in its own domain without inventing new dependencies. MakeWAY should use it to assemble reusable workflows; philosophy repositories should use it to govern design and reasoning; microsites should remain independent and composable.
